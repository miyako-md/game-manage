# 个人游戏资讯助手 · 需求文档

- 版本：v1.0（已确认，作为开发基线）
- 日期：2026-09-12
- 状态：**已确认（2026-09-12）**。补充决策：微信推送功能先行实现、SendKey 暂不配置；鸣潮按官服、战绩仅自己账号、标准轮询频率、Vue3 SPA 按默认执行

---

## 1. 项目定位与目标

个人使用的游戏信息聚合工具，核心解决三件事：

1. **监控**：对我关注/正在游玩的游戏做定时轮询，第一时间感知版本公告、活动开启/截止、体力恢复等变化；
2. **整合**：把分散在各官方社区、游戏平台的信息统一汇聚到一处，按"PC 游戏 / 手游（二游为主）"两大板块组织；
3. **提醒**：体力将满/已满、活动即将结束、版本更新发布等关键事件，通过系统通知等渠道主动推送。

**明确不做的事**（边界）：
- 不做多人共享/多用户系统，仅个人单用户使用；
- 不做代肝、自动战斗等游戏内操作类功能；
- 不破解加密、不绕过反爬的高对抗手段，仅使用社区已公开的接口方案，低频访问；
- 不承诺 100% 实时（信息源均无推送接口，采用轮询模拟准实时）。

## 2. 总体设计方向

采用**游戏适配器（Adapter）架构**：框架与游戏解耦。

```
┌─────────────────────────── 前端仪表盘（浏览器） ───────────────────────────┐
│   PC 游戏板块                │   手游板块（二游）                            │
│   账号卡片 / 战绩 / 公告 / 资讯 │   账号卡片 / 体力 / 活动日历 / 公告 / 资讯      │
└──────────────────────────────────┬───────────────────────────────────────┘
                                   │ HTTP
┌──────────────────────────────────┴───────────────────────────────────────┐
│  核心框架：调度器(APScheduler) + 存储(SQLite) + 通知(微信推送/可扩展)         │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐              │
│  │ LoL 适配器  │ │ 鸣潮适配器  │ │ 未来游戏 A  │ │ 未来游戏 B  │  …可插拔      │
│  │ 声明能力:    │ │ 声明能力:   │ │            │ │            │              │
│  │ 账号/战绩/  │ │ 账号/体力/  │ │            │ │            │              │
│  │ 公告/资讯   │ │ 活动/公告/  │ │            │ │            │              │
│  │            │ │ 资讯/签到   │ │            │ │            │              │
│  └────────────┘ └────────────┘ └────────────┘ └────────────┘              │
└──────────────────────────────────────────────────────────────────────────┘
```

- **能力模型**：框架定义一组标准能力接口（账号信息、体力、活动日历、公告、资讯、战绩、签到）。每款游戏的适配器声明"我支持哪些能力、数据从哪来"。
- **新增游戏流程**（回应"依据具体游戏名查询能获得的信息种类和渠道，再决定纳入哪些内容"）：
  1. 调研该游戏的可用渠道 → 输出"信息种类 × 渠道"清单；
  2. 和用户确认纳入哪些能力；
  3. 编写该游戏的适配器模块，注册进框架；
  4. 前端仪表盘自动按适配器声明的能力渲染对应板块。
- **凭据管理**：账号类凭据（Cookie/token）保存在本地配置文件中，不进代码库；失效时在仪表盘上明确提示"需要更新凭据"，而不是静默失败。

## 3. 功能需求

### 3.1 PC 游戏板块

| 能力 | 说明 | 优先级 |
|---|---|---|
| 账号信息 | 等级、段位、常用英雄等概览卡片 | P1 |
| 战绩查询 | 近期对局列表（英雄/胜负/KDA），点开看单局详情 | P1 |
| 信息公告 | 版本更新公告、维护公告、官方活动页 | P0 |
| 相关资讯 | 资讯流/赛事新闻聚合展示，来源可配置 | P2 |

### 3.2 手游板块（二游为主）

| 能力 | 说明 | 优先级 |
|---|---|---|
| 账号信息 | 等级、角色概览、资源概况 | P1 |
| 剩余体力 | 当前体力/上限/恢复满的预计时间，体力满推送提醒 | P0 |
| 活动安排及剩余日期 | 活动列表 + 起止时间 + 剩余天数，日历视图，临期提醒 | P0 |
| 更新公告 | 版本更新/维护公告 | P0 |
| 平台资讯 | 库街区/官方号/TapTap 等资讯流聚合 | P2 |
| 每日签到 | 游戏内签到（游戏外自动完成） | P2（顺手做） |

### 3.3 通用能力

- **配置中心**：管理已接入游戏、每款游戏的凭据、轮询频率、提醒开关；
- **主动提醒**：微信推送（Server酱/PushPlus 等）为首发唯一提醒渠道；**功能在框架阶段先行实现，SendKey 暂不配置**——未配置时提醒静默跳过，仪表盘显示"提醒渠道未启用"；通知渠道做成可扩展接口，后续可随时加 Windows 系统通知、邮件等；
- **数据缓存**：拉取结果落 SQLite，仪表盘读取本地数据；源站不可达时展示最近一次成功数据 + 更新时间戳；
- **手动刷新**：页面可手动触发立即拉取。

## 4. 首发游戏数据渠道调研

### 4.1 英雄联盟（PC）

| 信息类别 | 渠道 | 凭据要求 | 风险/备注 |
|---|---|---|---|
| 账号信息、战绩查询 | 掌上英雄联盟/WeGame 接口（参考开源项目 [lumingfei156/lol-api](https://github.com/lumingfei156/lol-api)） | 需抓取登录 Cookie | 非官方接口，Cookie 偶尔失效需手动更新 |
| 账号信息、战绩查询（备选） | LCU 本地客户端接口（客户端运行时可用） | 无需凭据 | 仅限本机、需客户端在运行 |
| 版本公告、更新说明 | 官网 lol.qq.com 页面爬取 | 无 | 稳定 |
| 相关资讯 | 掌盟资讯流、官网新闻 | 无/低 | 爬取，来源可配置 |

> 国服（腾讯）不在 Riot 官方开发者 API 覆盖范围内；若为外服账号则可改走 Riot 官方 API（更稳定，需申请 key）。**待确认。**

### 4.2 鸣潮（手游/二游）

| 信息类别 | 渠道 | 凭据要求 | 风险/备注 |
|---|---|---|---|
| 账号信息、剩余体力 | 库街区 API（接口文档收集：[Kuro-API-Collection](https://github.com/TomyJan/Kuro-API-Collection)），体力来自 getRoleData 的 energy 字段 | 需抓取库街区个人 token | 社区成熟方案（如 [Yunzai-Kuro-Plugin](https://github.com/TomyJan/Yunzai-Kuro-Plugin) 已验证）；仅支持官服 |
| 活动安排及剩余日期 | 库街区活动接口 + 官网公告解析整理 | token/无需（视接口） | 需自行解析成日历数据 |
| 更新公告/版本 | 库街区官方公告、鸣潮官网 | 无 | 稳定 |
| 平台资讯 | 库街区帖子流、B站官方号、TapTap | 无 | 多渠道可选，M3 后再接 |
| 每日签到 | 库街区签到接口 | token | 顺手实现 |
| 抽卡记录分析（可选扩展） | WeGame 鸣潮助手 / 库街区 | 另需凭据 | 不在首发范围 |

> 库街区方案仅支持**官服**账号（B 服支持情况需验证）。**待确认你的鸣潮是否官服。**

## 5. 技术选型（默认方案，可调整）

| 项 | 选型 | 理由 |
|---|---|---|
| 后端语言 | **Python 3.11+** | 库街区/掌盟等接口的社区参考实现几乎都是 Python，"抄作业"成本最低；爬取、定时任务生态成熟 |
| Web 框架 | FastAPI + Uvicorn | 自带 API 文档，异步支持好，与 httpx 配合自然 |
| HTTP 客户端 | httpx | 异步 + 易于控制超时/重试 |
| 存储 | SQLite | 单文件零运维，个人规模完全够用 |
| 调度 | APScheduler | 进程内定时轮询，无需额外消息队列 |
| 前端 | Vue 3 + Vite（SPA） | 仪表盘交互（自动刷新、日历、图表）体验好；如偏好极简可降级为服务端渲染 |
| 提醒 | 微信推送（Server酱 / PushPlus） | 用户确认的首发渠道；功能先行实现，SendKey 暂缓配置（未配置时静默跳过） |
| 部署形态 | 本机常驻进程（可注册为 Windows 服务/开机自启） | 个人工具，单机运行 |

## 6. 非功能需求（默认值，可调整）

- **轮询频率**（全局可配置）：体力类 5 分钟；活动/公告类 1 小时；资讯类 4 小时。低频、克制，避免对源站造成压力；
- **失效处理**：凭据失效 → 仪表盘醒目提示 + 系统通知提醒更新；接口结构变化（非官方接口常见）→ 该项能力标记"暂时不可用"，不影响其他能力；
- **安全**：凭据仅存本地配置文件（.gitignore 排除），日志不打印凭据；
- **合规**：仅个人使用、低频访问、使用社区公开接口方案，不用于任何商业用途。

## 7. 里程碑规划

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M0 项目框架 | 目录结构、配置中心、SQLite、调度器、适配器接口、通知接口 + 微信推送渠道实现（不配置）、前端骨架 | 框架空跑通过，页面可访问，模拟通知可触达推送接口 |
| M1 鸣潮适配器 | 账号信息、剩余体力、活动列表（含剩余天数）、更新公告 | 仪表盘能看到真实鸣潮数据 |
| M2 LoL 适配器 | 版本公告、资讯 + 账号信息、战绩查询（Cookie 接入） | 仪表盘能看到真实 LoL 数据 |
| M3 提醒与日历 | 提醒规则引擎（体力满/活动临期判断与触发）、活动日历视图；SendKey 配置后即可真实收推送 | 断网/临期场景验证 |
| M4 打磨 | 手动刷新、签到、资讯聚合、第二轮游戏预留评估 | 按清单逐项验收 |
