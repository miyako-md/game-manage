# 个人装备权重评分

在已授权账号的角色详情选择“配置权重与 A/B 对比”。分别填写个人权重模型、复制已采集装备并核对缺失输入，或手动添加装备；保存两份配置后选择 A/B。双方总分、单件小计和逐词条贡献在当前同一模型下重新计算。JSON 导入/导出仅为折叠的高级入口。截图模式共用详情组件，读取后端已授权的评分摘要，不执行浏览器 API 或写入。

分数表达偏好，不是官方伤害、装备最优解、跨角色或跨用户排名。鸣潮有内置的非官方默认权重（见下节）；异环没有内置权重、品质因子、面积或主词条参考值。缺输入保持 null；未配置、不可评分与已知零分分别呈现。一个装备不可评分时套装总分为空，可保留其他已知装备的小计并明确标为部分结果；全部未知时不显示零小计。

## 鸣潮默认评分（非官方）

没有保存个人模型时，鸣潮角色使用内置默认权重 `src/game_assistant/assessment-defaults-wuwa.json`，结果 `origin=builtin_default`、`unofficial=true`，网页与 QQ 图标“默认评分 · 非官方”。优先级：用户保存的模型（整体替换默认，不逐项合并）> 内置默认 > 未配置。DELETE `/model` 删除个人模型即恢复默认；PUT 只接受 `source=user_configured`，把默认模型另存为个人模型时去掉 `attribution`，仍按下面的声骸公式计分。

- 公式 `wuwa-echo-default-v1`，复刻 WutheringWavesUID：单件分 = Σ(词条显示值 × 权重) ÷ 该 COST 理论满分 × 50；主词条（含随 COST 固定的第二主词条）按声骸 COST 1/3/4 取权重，副词条用副词条权重；百分比词条按显示的百分数数值计，平值按原值计。等级按单件分 ÷ 50 的占比 0/0.48/0.6/0.7/0.78/0.84 定 c/b/a/s/ss/sss；总分为各件单件分之和，满分 250，总等级按总分 ÷ 250。
- 理论满分不入库，加载时按权重 × 游戏内单条最大值和每个角色的满分词条组合复算；与上游 45 份 `score_max` 都一致（上游存的是浮点截断到 3 位的值，差小于 0.003）。
- 与上游的差异：取整用 HALF_UP 两位（上游向下截断），满分用精确值；菲比“新光套”等按套装切换的变体忽略，只用 `calc.json`。技能伤害已按 `skill_weight` 展开，属性伤害只计角色本属性。
- 覆盖：上游快照 46 个角色 ID（`attribution=gpl_snapshot`，署名“权重改编自 WutheringWavesUID（GPL-3.0）”）；12 名上游未覆盖的角色为自制权重（`attribution=self_made`，署名“自制权重”）：绯雪、洛瑟菈、穗穗、莫宁、爱弥斯、达妮娅、丽贝卡、心、清宵、琳奈、露西、秧秧·玄翎。其余角色没有默认权重（网页显示“暂无默认权重”，QQ 图不显示评分块），不回退通用模板。
- 已装备声骸取自库街区角色详情：每件带 `cost`，主副词条都是数组且每项都能解析时视为完整（D2，只限装备快照）。缺 COST 或 COST 不是 1/3/4 的那件判不可评分（`UNKNOWN_COST`），计入部分结果，不按 0 分；主副身份未知为 `UNKNOWN_STAT_ROLE`。
- 新增结果字段：顶层 `origin`、`unofficial`、`attribution`、`grade`、`max_value`（250）；`item_results[]` 的 `cost`、`grade`、`max_value`（50）。用户 Σ 权重模型这些字段为 null（`origin=user_configured`）。

| 游戏 | 公式与输入 |
| --- | --- |
| 鸣潮（用户 Σ 权重模型） | `Σ(词条规范值 × 用户权重)`。平值单位 flat；ratio 是比例；percent_points 是百分数数值部分，除以 100。权重 0..100。词条 ID 按攻击/生命/防御的平值与比例分别建模，暴击、暴伤、共鸣效率、各伤害加成独立。主副词条观察标识分开，同一观察重复只计一次，冲突或不明重复拒绝。只有用户明确核对完整列表后，未出现的词条才按零计。 |
| 异环 | 分母 D 为有效副词条最高四项正权重之和。驱动副项 `10 × 面积 × 品质因子 × 权重 / D`；卡带副项 `100 × 品质因子 × 权重 / D`；卡带主项 `50 × 权重 × 当前值 / 正参考值`。副项是词条存在性的偏好加权，不按副项数值推断游戏强度。输入要求显式类型、品质、驱动正整数面积、完整副词条、词条 ID/单位/观察标识；卡带还要求主项值及匹配的参考上下文。 |

NTE 只提取本项目独立库存分支 `fa67785f9842d429a60c6a11d00f10e59372dd66` 的单件纯数学、必要类型与合成 golden；不导入库存数据库、采集、Windows、OCR、会话或排名模块。所有分数用 Fraction 精确累计，最后 HALF_UP 两位；A/B 差值和百分比也基于精确分数，A 精确值为零时百分比为空。模型内容指纹及版本随结果保存。配置不会携带历史分数，变更模型后双方重算。

NTE 富字段来自固定 NTEUID schema `8fc59ff35b7fdbd1e31bf6b15ec4ba0c8d36b7cb` 的结构核验，不是实际账号响应。保留 `core/pie` 来源分组，不能推断装备类型、品质、面积、列表完整性。没有读取/运行外部评分包或 waves_build 二进制；异环没有复制第三方游戏权重资源（鸣潮默认权重的来源与改动见 THIRD_PARTY_NOTICES.md 的 Bundled derived data）。现有 API 响应中的这些未知输入保持未知；用户手动提供的模型/更正输入标为 `user_configured`。源装备 ID 单独保留，配置内槽位 ID 使用分组及位置，不代表完整库存身份。

本地接口前缀 `/api/assessment/{game}/{character}`；云端接口前缀 `/api/accounts/{account_id}/roles/{role_id}/assessment/{game}/{character}`。GET 根路径读取模型/配置（没有个人模型时返回内置默认或 `unconfigured`）；PUT `/model` 保存模型；DELETE `/model` 恢复默认；POST `/configurations` 保存配置；DELETE `/configurations/{id}` 删除配置；GET `/equipped` 只读现存快照/归档；POST `/score` 评价配置；POST `/compare` 重新评分两个保存 ID。云端每次由网站会话解析用户与授权 scope，校验游戏、授权版本和 CSRF；本地由当前适配器账号解析 scope。请求流上限 128 KiB，每角色最多 64 个保存配置。保存文件为对应数据根目录下 `personal-assessments.db`，按用户/账号/游戏角色/游戏/角色 ID 隔离。

真实 NTE 装备字段、Linux Chromium 与真实 QQ 收图均未验收。鸣潮装备字段（声骸 `cost`、`main_props`/`sub_props` 数组、`phantom_prop.phantom_id`）已对照真实缓存的结构核对，不含数值；完整性按上节 D2 约定。本次只能确认合成 fixture 的解析、数学、权限、UI 与隔离浏览器行为。
