# 鸣潮扩展使用与数据说明

本轮范围：账号档案与收集、角色和实际装备、挑战战报、更多玩法、资源报告、抽卡导入与出金统计、深塔和角色成长档案。界面继续使用项目既有的藏蓝与金色。

## 数据如何取得

账号、探索、角色摘要及挑战等周期性数据，沿用已登录的库街区账号和项目快照机制。角色完整面板按点击读取；资源周/月/版本报告按官方返回的可用周期读取。无需新增登录方式。

| 内容 | 官方来源 | 读取方式 |
| --- | --- | --- |
| 档案、成就、信标、奇藏箱和潮汐之遗分类 | roleBox `baseData` | 周期快照 |
| 探索比例、残象探寻、数据坞 | `exploreIndex`、`calabashData` | 周期快照 |
| 角色摘要／完整面板和装备 | `roleData`／`getRoleDetail` | 摘要定期采集，详情按需 |
| 深塔／全息／冥歌海墟 | `towerDataDetail`／`challengeDetails`／`slashDetail` | 周期快照，分来源保留状态 |
| 更多玩法 | `moreActivity` | 按实际返回的玩法名称展示 |
| 星声和贝币获取 | resource `period/list` 及周／月／版本报告 | 默认月报告，其余按需 |
| 抽卡 | 官方 `gacha/record/query` 或本地导出 JSON | 用户主动导入 |
| 跨期成绩及练度变化 | 本项目的有效观察记录 | 本地归档与有限回补 |

实际装备武器与角色使用的武器类型是不同字段；角色详情中的武器、声骸、主副词条、技能及共鸣链来自完整面板。当前接口不代表全部声骸背包，也不包含官方评分或伤害预测。

深境区是深塔界面的默认分区。全息挑战和冥歌海墟分别保留来源状态；某一来源失败不会清空其他成功数据。保留的旧数据应同时显示其时间与失败状态。缺失值表示未知，不能视为零或已完成。

星声／贝币简报表示所选周期的**获取量**，不是当前钱包余额。探索完成比例和收集数量也分别展示，不能将可能重叠的宝箱分类相加后当作独立总数。

## 抽卡记录由用户决定何时导入

在本机导入入口粘贴游戏内记录链接，或选择已有 JSON 导出。普通页面加载、刷新与历史回补不会自动抓取抽卡记录。

链接只用于提取本次查询需要的参数；后端向固定官方抽卡查询地址请求，不访问任意输入网址。链接及记录授权参数不写入数据库。导入时核对当前账号及区服，避免串档。

重复导入保留已知记录，并兼顾同一秒出现多个相同物品的真实情况。统计仅描述已导入范围：各池抽数、稀有度分布、五星明细及覆盖时间。官方可返回窗口之外的旧记录，需要已有导出文件才能回补；最早记录时间不等于账号创建时的完整历史。

本轮不推算保底、大小保底或必定出金次数。

## 从启用起积累历史

成功的角色列表采集与深塔战报形成账号、区服隔离的本地档案；角色详情在实际查看后保存。失败数据或标为旧快照的战报不会作为一条新成绩。内容没有变化时不会仅因采集时间变化产生一条“练度提升”。

跨期成绩只有在对应周期被实际记录后才能比较。角色练度变化至少需要两次有效观察；刚启用时只有基线是正常情况。账号切换后按当前账号读取档案。

回补只使用现有可确认归属的快照及接口实际能提供的数据。无法获得的历史保留缺口，不生成推测成绩。版本名称仅使用有来源的值，无法确认时以开始记录日期说明覆盖范围。
