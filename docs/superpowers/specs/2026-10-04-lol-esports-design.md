# LOL 职业赛事、战队与选手设计

日期：2026-10-04
状态：待用户书面评审；本设计尚未批准，未编写实现计划，未开始产品实现。
适用安装：`game-manage/`，正式服务 `http://127.0.0.1:8010`。

## 1. 用户目标、确认事项与本次设计提案

用户希望在游戏管家的 LOL 模块查看职业赛事，并能够查看相关战队和选手，服务于观赛及了解参赛者。该功能不组织用户参赛，也不读取个人职业比赛数据。

已经明确的用户要求：

- 先覆盖 LPL 和国际性赛事，不接入其他地区联赛。
- 包含战队、选手。
- 暂时不用开赛提醒。
- 首版先用腾讯电竞数据；腾讯是唯一数据接入，不注册外部服务，不引入 API 密钥。

本文件将此前交流中的建议具体化，供用户一次书面审核：在 LOL 中增加“职业赛事”，提供当前赛季赛程赛果、战队阵容与选手资料。国际赛事提案限定为全球先锋赛、MSI、全球总决赛、电竞世界杯的英雄联盟项目，以及亚运会的英雄联盟项目。赛事详情包括已取得的比赛时间、对阵、系列赛比分、阶段、赛制和官方直播／回放链接。这些具体清单与交互以本文件获批为准；选择腾讯数据源不等于已批准本设计或后续实现计划。

关注战队、收藏、个性化推荐、选手深度统计均不是用户明确要求，首版不纳入。赛事／日期／战队的普通列表筛选仅用于浏览，不保存关注关系。

## 2. 范围与“当前赛季”的定义

### 2.1 纳入规则

以北京时间所在公历年作为首版赛季年份。2026 年启动时默认范围为 2026：

- LPL：腾讯明确归入职业联赛的该年度比赛，包含该年度各赛段、季后赛和归入该赛季的资格赛。不能只按赛事目录的结束日期截断比赛。
- 国际赛事：仅接纳第 1 节列明的赛事家族中由来源明确标识为该年度／届次的英雄联盟比赛。亚运会不按每年必有处理；资料缺失不能推断该年不举办。
- 战队与选手：限于上述范围的参赛队伍及其来源可得的阵容成员，包括参加国际赛事的海外队伍、国家／地区代表队；纳入这些队伍不意味着接入其所属地区联赛。
- 一项年度赛事横跨年末时，以来源明确的赛季归属为准，其跨年比赛仍属于该赛季。年份由正常轮询重新评估，不要求用户重启应用。

不纳入德玛西亚杯、LPL 全明星、次级或挑战者邀请赛、其他地区联赛、娱乐赛、解说杯、云顶之弈／金铲铲等项目。不得把“腾讯列表内存在”自动当作“属于本产品范围”。

来源的赛事家族 ID 与当年赛季 ID 分开处理：家族使用经样本核实的映射，当年实例从目录解析，禁止把 2026 的具体赛季 ID 写成永不更新的固定值。未识别的新分类进入“尚未支持／待核验”，不按名称相似度自动纳入。家族规则的扩展属于后续范围变更。

### 2.2 历史与缺失

首版不提供跨年历史赛季浏览和全量历史回补。切年后不把上一年赛事包装成当前赛事；新年度采集尚未成功时保留旧快照，但当年视图显示“本年度资料尚未取得”，旧值不混入当前列表。有效新年度数据包发布后，按现有“最新快照”语义替换展示缓存，不承诺保存跨年职业历史；这不删除或更改已有个人归档、其他游戏数据或凭据。一次失败或未知覆盖的空响应不触发缓存清空。

“仅展示有数据”是指不生成虚构对阵、选手或比分。范围内的赛事仍可显示明确的可用性提示，例如“腾讯尚未提供本年度资料”，不让整项赛事消失后造成已覆盖的错觉。

## 3. 工程基线与来源证据

### 3.1 可复用工程能力

- `adapters/league_of_legends/adapter.py`：现有能力是账号、个人对局、统计、公告和资讯；职业赛事尚无实现。
- `adapters/league_of_legends/lol_news.py`：提供 HTTPX 客户端、JSON／JSONP 解析及异常隔离范例。CMC 的赛事栏目可用于新闻，但不是赛程或阵容数据。
- `snapshots.py`、`scheduler.py`、`api.py`：已有 SQLite 最新快照、轮询锁、失败保留旧值、采集状态和过期判断。
- `LolDashboard.vue`：当前有个人总览、对局记录、海克斯、公告与资讯；顶部筛选与空态主要围绕个人归档。
- `calendar.js`：北京时间解析、格式化和安全外链工具可复用。`GameEvent` 是游戏内活动，不适合作为职业比赛的主模型。
- `Capability.TEAMS` 的现有用途是异环配队，不复用为职业战队；个人 `MatchSummary`、LCU 归档也不承担职业比赛。

设计以本机当前工作树为基线，包括尚未提交的 B 站登录和四游戏统一资讯补丁，不以重置到 Git HEAD 为前提。

## 4. 产品交互

LOL 原有页签中新增“职业赛事”，页内提供“赛程赛果”“战队”“选手”三个视图。沿用现有组件、主题和窄屏样式，不创建独立站点。

### 4.1 赛程赛果

- 默认按北京时间日期展示当前年份已取得的比赛；有未来比赛时定位最近比赛，否则显示最近赛果。
- 支持范围内赛事及日期过滤，显示系列赛级别的对阵、比分、状态、阶段、BO 赛制和来源。
- 未开赛但比分字段是 0／空时显示未开赛或“—”，不把占位比分解释为结果。状态不能仅由当前时间超过计划开赛时间推断为进行中或已结束。
- 待定队伍、待定时间、延期、取消、未知状态分别保留其语义；未核实的状态码映射显示“状态待核实”。比分与胜者矛盾时提示结果待核实，不自行判胜。
- 直播／回放仅展示来源明确提供或已验证的官网路由链接，外部打开。缺失时标明暂未提供；不猜测视频 ID，不嵌入自动播放，不保证第三方直播在线。
- 点击战队进入本模块的战队视图；返回赛程保留所选赛事与日期。

### 4.2 战队与选手

- 战队列表按当前范围的实际参赛关系构建，显示队名、简称、可用标志和所属赛事；目录存在但未确认参赛的队伍不自动纳入。
- 战队详情显示官网简介、可得阵容、成员位置与相关赛程；点击选手进入选手详情，点击比赛返回相应赛程位置。
- 选手列表来源于范围内战队的可得阵容，显示游戏昵称、可得头像、位置及来源明确的队伍关系。选手详情展示这些基本资料及来源链接，不承诺年龄、合同状态、完整转会史或技术统计。
- 位置编码必须根据官方页面逻辑及样本核实映射，未知值显示“位置暂缺”。有多名同位置成员时全部保留，不能自行认定首发；无明确标记不区分替补和教练。
- “官网当前阵容”是来源对 activePlayers 的声明，不是本产品对实时现役资格的独立认证。每个阵容区块展示其采集时间和源更新时间；旧资料显式标注可能滞后。
- 历史阵容与当前阵容分开。首版不展示完整历史转会列表；如果比赛没有单场出场名单，显示“本场出场阵容暂缺”，不能套用当前阵容。
- 国家／地区代表队与俱乐部是不同队伍实体，选手可能同时有不同类型的关系；不因其代表队关系覆盖或推断俱乐部所属。

### 4.3 空态与更新入口

首次没有缓存时显示“尚未采集”，提供独立“更新赛事”入口。该入口只更新公开赛事资料，不触发客户端战绩采集，也不依赖 B 站登录。

个人档案的无数据提示、模式筛选、采集按钮与分析错误只在个人相关视图起作用；不能遮挡赛事、战队和选手视图。LOL 客户端关闭或切换账号时，职业赛事缓存与浏览状态仍可用。

不把职业赛事写入全局活动日历，不创建提醒、通知订阅或推送。失败状态也仅显示在赛事界面与采集状态中，不通过现有通用失败提醒间接发送赛事通知。

## 5. 数据模型与身份关系

职业赛事采用独立公开能力 `esports`，其快照为版本化数据包，含赛事实例、系列赛、战队、选手和阵容关系，以及各分组的来源／完整性状态。首版不增加通用多供应商框架或职业统计数据库。

| 实体 | 最小字段与关系 |
| --- | --- |
| 赛事实例 | 来源、赛事家族、赛季 ID、年份、名称、可得阶段；目录起止日仅作元信息 |
| 系列赛 | 来源比赛 ID、赛事实例 ID、双方战队 ID、带时区的计划开赛时间、状态、系列赛比分、BO、阶段／轮次、官方链接 |
| 战队 | 来源战队 ID、队名／简称、标志、简介、来源明确的队伍类型、当前范围参赛关系 |
| 选手 | 来源选手 ID、游戏昵称、可得图片及位置；身份不由队名或昵称拼接 |
| 阵容关系 | 战队 ID、选手 ID、关系范围（官网当前／赛季报名／单场出场）、可得有效期、来源及观测时间 |
| 资料状态 | 所属分组 ID、最后尝试、最后成功采集、源更新时间、覆盖状态、错误状态、过期标记 |

所有主键以 `tencent:` 加实体类型及源 ID 形成命名空间，并保留原始 ID 字符串。赛事家族、赛季、系列赛、单局 ID 不混用；超过 JavaScript 安全整数范围的编号不得转数值。单个源 ID 语义不明时不作跨表强行合并。

相同昵称／简称不是合并依据，队伍改名不创建新的身份推断。转会改变阵容关系，不改变选手身份。重复源 ID 内容冲突时保留上次可信版本并标记异常；缺外键时可以保留比赛及来源给出的名称，但不伪造可点击的战队／选手实体。

计划时间和资料时间以带时区 ISO 时间存储；腾讯无时区文本按经页面核实的北京时间解释，异常日期和 `0000-00-00` 转为未知。比赛未给结束时间时不按 BO 估算后写入。

## 6. 集成架构与数据流

复用现有 FastAPI、HTTPX、Pydantic、SQLite 和 APScheduler，无新增服务和依赖的设计前提。

1. 腾讯公开数据客户端：固定官方来源和有界请求；读取目录、当年分赛事赛程、必要的战队资料；仅把 JavaScript 数据赋值包装剥离后按 JSON 解析，绝不 eval 或执行脚本。
2. 纯解析与归一化层：校验形状、业务状态、ID、年份、范围、时间与关联；输出类型化结果及覆盖信息，不接触 LCU、凭据和数据库。
3. LOL 赛事编排：按赛事／队伍分组更新，合并上次成功数据，计算各组状态，发布一致的数据包。战队／选手资料失败不阻止有效赛程展示。
4. 现有快照与轮询体系：通过新增 `Capability.ESPORTS`、适配器方法与间隔配置保存公开快照；加入公开数据分类，确保换账号不会清除；赛事轮询绕开提醒引擎。
5. 前端独立赛事组件：读取公开快照，进行列表筛选和联动，复用日期、外链和加载／取消请求习惯，不让个人归档请求决定赛事可见性。

读取沿用 `GET /api/games/league_of_legends/snapshot/esports`，只读取本地缓存。独立 `POST /api/lol/esports/refresh` 触发该能力更新，复用现有写请求保护和同一轮询锁，不转发客户端指定的上游 URL。该路径是本设计提出的接口，尚未实现。

首版快照响应提供 schema_version、season_year、catalog、tournaments、matches、teams、players、roster_memberships、coverage、refresh_state。前端不解析腾讯原始字段，不将任意原始响应传给用户。

兼容现有整游戏刷新时，只把赛事作为隔离的公开能力参与，赛事失败不能影响原有能力成功保存；独立赛事更新不能顺带调用整游戏刷新。

## 7. 缓存、时效、失败与数据覆盖

### 7.1 更新时间的含义

- `last_attempt_at`：本机最后一次尝试访问该分组，不表示成功。
- `last_success_at`：本机最后一次取得并通过结构校验的该分组资料。
- `source_updated_at`：来源自身声明的更新时间；来源没有提供则为空，不能用抓取时间代替。
- 顶层 `fetched_at`：本地数据包发布的时间，不代表每支战队／每项赛事都更新成功。

页面分别标明“采集于”和“腾讯数据更新于”。即使今天成功抓到三个月前的阵容，也不显示为“阵容今天已更新”。源更新时间不能作为内容完整性的证明；不合理的未来时间、无效时间记录异常且不用于提高新鲜度。

### 7.2 首版更新策略提案

- 复用周期任务，默认每 15 分钟检查当前年份赛程；这是近实时缓存，不承诺实时比分。
- 赛事目录与战队／选手资料默认每 24 小时更新；新出现的参赛队首次遇到时允许补取一次。手动更新只请求已经到期或尚缺的分组，不强制重抓整库。
- 同一赛事刷新最多一个在途，手动入口至少间隔 60 秒；并发最多 3 个上游请求，单请求超时 15 秒。遵从 Retry-After；429／访问限制不立即重试，不使用代理、伪造登录或其他来源绕行。
- 赛程超过 30 分钟无成功采集，目录或阵容超过 48 小时无成功采集，标记“缓存可能过期”。这些是本产品缓存阈值，不代表来源保证。
- 若源阵容更新时间超过 7 天，额外提示“官网资料可能滞后”；缺源更新时间则显示“源更新时间未知”。该提示与本机缓存过期分别计算，7 天也是提示阈值而非阵容有效期。
- 首版不设置界面打开即高频外网轮询；查看缓存不引起网络采集或数据库写入。

### 7.3 完整性、部分成功与空结果

覆盖状态与请求状态分开保存：

| 情况 | 数据处理与界面 |
| --- | --- |
| 从未采集 | 尚未采集，不显示“无比赛” |
| 当年赛事实例缺失 | 本年度资料暂缺，不回退旧年度冒充 |
| 赛事存在但列表未能证明完整 | 数据可能不完整；有记录就展示记录，无记录仍提示资料暂缺 |
| 可信完整分组中，用户筛选结果为零 | 当前筛选暂无比赛；这只描述本地已取得范围 |
| 来源明确声明某范围没有安排 | 显示官方暂未安排，并保留相应来源依据 |
| 网络／结构／业务状态错误 | 保留旧数据并标记更新失败；无缓存则显示暂不可用 |
| 部分分组成功 | 成功分组更新，失败分组保留旧值及原时间；顶层显示部分更新 |

缺项、未知覆盖的空列表或一条坏记录不能触发旧数据清空。归一化时允许展示可校验的有效记录，同时将所属分组标记部分；对无法证明完整的增量结果按稳定 ID 合并旧记录，不根据“这次没返回”推断删除或取消。来源明确的取消／删除才改变相应比赛状态；来源确认完整列表的替换也需针对同一赛季与查询范围。

合并只发生在同一赛季、同一实体分组内，不把旧年度记录合并成新年度资料。完整性不能由 HTTP 200、文件更新时间或抽样正确推导；只有来源明确的完整列表语义、分页／范围条件和全部记录校验同时满足才标记完整。当前没有足够证据的腾讯分组保持覆盖未知或部分，不因成功刷新自动升级为完整。

一次刷新取得有效分组时，可发布包含旧分组的新快照；通用 poll_status 的成功仅表示数据包已发布，业务健康必须读取 payload 中的各分组状态和 overall partial 标记，不能把所有卡片统一改为最新。全部请求失败则返回失败并保留旧快照，API 将最近失败状态叠加到旧数据展示。首次仅取得目录但缺比赛时可保存目录和明确的缺失状态。

不把汇总列表当作全量依据。赛事目录选择年度实例，优先读取该实例的分赛程列表；如该列表缺失，不能用汇总中零条匹配记录作为“没有比赛”的证明。目录年份缺失本身保留为产品可见的覆盖缺口。

## 8. 来源访问与既有功能保护

固定允许的腾讯官方来源，正常校验 HTTPS。响应形状、大小与数量有界，站外重定向不自动跟随；若必要数据出现新域名，先核实来源后再适配。前端仅打开通过协议检查的官方来源链接，正文采用现有安全文本展示方式，不执行来源 HTML。

不需要 Riot 密钥、腾讯账号、B 站 Cookie 或 LCU token。公开赛事缓存不写入个人战绩表，不随个人账号变更失效；关闭游戏客户端不影响读取。资料图片失败使用占位图，不使整张战队／选手卡片失败。

本阶段仅新增本设计文件；不修改 config.toml、数据目录、服务参数、依赖、B 站登录及统一资讯补丁，不刷新或重启 8010，不更改 Git 身份。后续实现必须保留现有未提交工作，以具体差异实施，禁止用整文件旧版本覆盖已有补丁。

## 9. 后续测试与验收标准

本节是验收要求，不是实现任务顺序。本阶段不执行应用测试、不运行刷新，也不声称功能已经通过验收。

| 验收主题 | 必须验证的行为 |

| 范围 | 只包含当年 LPL 与获批国际赛事；不混入其他联赛、德杯、次级邀请赛、TFT；跨年归属正确 |
| 目录问题 | 复现 Worlds 目录年份缺失、LPL 目录结束日与比赛日期冲突；不隐藏有效赛程，不伪造当年赛事 |

| ID 与关系 | 字符串大 ID、重复／冲突 ID、改名、同昵称、转会、国家队／俱乐部并存、缺外键 |
| 阵容 | 当前名单不填充历史比赛；未知位置不猜测；多同位置保留；旧海外队资料明确标注 |

| 隔离 | LCU 关闭、无个人归档、切账号仍可看赛事；赛事更新不采集个人战绩，不要求 B 站登录 |
| 无通知 | 赛事不写入活动日历，不进入开赛、临期或通用采集失败通知 |

解析测试使用有来源、抓取日期和覆盖说明的固定公开样本。端到端上线前抽样对照腾讯官网中的一场 LPL、一项可得国际赛事、一个 LPL 战队和一个国际参赛队；核验时间、比分、ID、位置和链接，记录来源缺口，不能用样本成功宣称所有赛事完整。

出现当前年份国际赛事缺项时，“功能正确地显示来源暂缺”可以通过降级验收，但不能宣称该赛事已完成数据覆盖。接口真实可用性与产品降级正确性分别汇报。
