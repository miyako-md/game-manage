# 异环资产、角色工具与抽卡账本扩展

用户已要求执行房产详情、载具详情、官方配队推荐、角色筛选/排序/收藏/对比和完整抽卡历史管理，并明确抽卡所需接口。沿用当前本地 FastAPI + Vue 深蓝金色界面。

## 资产与推荐

增加 realestate、vehicles、teams 三项能力，各自独立记录快照和采集状态。房产与载具使用已登录角色查询；官方配队使用公开 team 接口，不提交登录凭据。房产展示拥有状态、入住角色和家具；载具展示拥有状态、基础/进阶属性和涂装；推荐展示官方标题、描述与图片。支持搜索和拥有状态筛选。原始缺失数值不转换成零，图片/链接仅 http(s)，禁用任意 HTML 渲染。

## 角色工具

保留已有角色详情，新增名称搜索、品质/元素/收藏筛选，等级/觉醒/混频/名称排序。收藏按 game_id + role_id 在浏览器本地保存，缺失账号身份时禁用持久化。对比允许 2–4 名角色，显示基础数据、弧盘、属性、战技/城区技能；缺失属性显示未提供。未知属性单位不强行换算，收藏不上传社区。

## 抽卡

独立本地逐抽账本，与已有社区出 S 统计分开展示。先核查 NTEUID 的逐抽导出和日志入口；未验证的官方历史 API 不提供虚假的自动同步按钮。最低可用完整交付为文件导入、校验预览、按账号与池去重持久化、记录筛选、导出以及有证据边界的垫抽统计。

导入必须包含角色身份、卡池身份、每抽物品/品质/时间和能稳定区分每次抽取的记录标识；重复导入不重复计数，冲突不覆盖旧记录。历史完整性、顺序及是否覆盖最新抽取必须明确，社区仅出 S 明细不得混入逐抽账本。缺少连续记录、池继承规则或官方保底规则时显示未知和缺项，不能编造当前垫抽或必出 UP。导入仅在本机保存，导出不含 token。

## 验证与交付

使用独立临时数据库/测试角色验证导入，不写入用户真实测试记录。完成纯解析与持久化测试、组件交互测试、全量后端/前端检查、生产构建、服务重启、真实只读资产接口和浏览器检查。记录实际可用、未验证和需要用户提供记录的部分。接口契约的调研结果纳入抽卡说明文档。
