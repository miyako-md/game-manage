# 可靠性与本地常驻设计

用户要求：写方案直接开始。承接上一轮建议，范围为提醒规则、后台采集状态、启动常驻及相邻的正确性修复。网页配置中心、活动编辑、签到、历史分析不在本轮。

## 1. 提醒与采集可靠性

- 每日去重按北京时间零点换日；活动提醒以真实剩余秒数判断，严格在0<剩余<=N*86400内触发。文案向上取整天数，时区为UTC+8。逆序日期不提醒。
- 结构化区分 offline / unconfigured / auth_expired / source_error / invalid_data / account_changed；前两种正常不可用不累计故障告警，账号切换旧请求不落状态、不推送。
- 没找到版本公告、正文为空或无法解析活动时返回异常并保留最后成功日历。手填非空但全部无效同样不得覆盖；显式手填配置为空仍走现有自动解析，不新增配置项。
- 快照库增加独立采集状态表，记录最后尝试、最后成功、状态、错误种类/信息、连续故障次数。只暴露归一化错误，不保存凭据/原始HTTP请求。
- 单个游戏能力的定时采集与手动刷新串行，避免同能力并发覆盖状态。保留账号版本检查。

## 2. 状态 API 与前端

- /api/status 保留notify，新增collection数组；每个已注册能力都有状态，首次未采集为never。
- snapshot接口新增poll_status字段；采集异常时旧数据可继续展示，但显式标明保留旧数据及来源异常。
- 游戏详情展示按能力的采集状态、最后成功/尝试、连续失败与原因；首页反映离线/未配置/失效/异常，日历可见后台采集失败。
- 旧卡片统一北京时间；重置时间到达即显示已可重置；LoL详情给每次选择请求编号，过期结果不可写入当前详情或清除当前加载状态。
- 不改变现有人工短信/CAPTCHA流程，不发送测试短信或真实微信通知。

## 3. 本地运行交付

- FastAPI托管frontend/dist，API优先，缺失静态资源返回404，未知/api路由不得返回SPA。默认127.0.0.1:8010。
- scripts/start.ps1 / stop.ps1 / status.ps1 / restart.ps1：工作目录固定项目根，隐藏启动，仅管理本项目验证过身份的进程；启动幂等，健康检查同时验证项目身份，失败给出日志路径。
- 日志和运行PID记录放data/runtime（已gitignore），日志轮转/上限策略明确。开发模式5173继续兼容，正式使用8010单端口。
- scripts/autostart.ps1 -Enable/-Disable/-Status：当前用户登录时隐藏启动，可撤销，无管理员服务、无公网页面暴露。实施默认交付入口并测试注册/删除；是否保持启用状态在验收记录中明确，不静默新增无法撤销的常驻项。
- 为启动瞬间补采集提供方案，但不因一次启动并发大量上游请求；默认保留原轮询频率，首次加载明确显示尚未采集。

## 验收

红→绿行为测试覆盖北京时间跨日、严格临期边界、预期离线免告警、失败保留日历、状态重启持久化/恢复/账号清理、同能力锁、API旧快照状态；前端覆盖源状态、未知值、时区与详情请求竞态。
隔离临时库测试，真实运行只重启本项目并读取已有快照/健康。验证单端口页面、API、受管进程、重复启动、停止重启与开机启动撤销。全量后端/前端回归和浏览器检查后独立审查。
