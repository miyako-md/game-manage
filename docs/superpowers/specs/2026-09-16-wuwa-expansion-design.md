# 鸣潮资料、战报与历史扩展

用户已选定开发范围并要求执行，沿用上一轮逐项对比和只读实测结论。

## 范围

实现完整账号档案、探索收集统计、深境区分层战报、角色墙筛选排序、角色完整属性/技能/共鸣链面板、实际武器和装备声骸详情、全息挑战、冥歌海墟、多玩法进度、星声/贝币资源简报、抽卡导入历史与出金统计、跨期深塔档案、角色练度变化。
仅评估保底分析的接口/导入方案，以及 GitHub 上可复用的声骸评分/配装比较/伤害计算实现，不实现这些计算。

## 架构及数据边界

- 保持 FastAPI + SQLite + Vue，继续使用已有库街区登录与 b-at 续期；不新增登录流程。
- 扩展原 account.extra 和 roles 条目；增加 combat、activities、resources 能力，用现有快照/轮询/采集错误契约。
- 复杂模型放 adapters/wuthering_waves 扩展模块，原有摘要字段兼容。未知保留 null，不能伪造零、满星或历史。
- 从 baseData 保存创建日期、世界等级、活跃天数、成就/星数、信标、奇藏箱与潮汐之遗分类（按实测名称）；探索进度仍保留现有语义。
- towerDataDetail 保存全部分区和层级，默认只展示 difficulty=3 深境区；seasonEndTime 是剩余毫秒，过期周期不可作为本期发布。
- getRoleDetail 保存 roleAttributeList、skillList、chainList、weaponData、phantomData 等实际字段；角色 id 必须属于当前账号角色列表；图片/来源链接仅 http(s)。
- challengeDetails、slashDetail、moreActivity 各自单独解析和报错；某子接口失败不得使其他成功结果消失。
- period/list 返回可用周/月/版本周期；默认读取最新月，切换只允许该账号已返回的合法类型/周期；报告是获取量而不是钱包余额。
- 抽卡使用官方固定 gmserver-api.aki-game2.com / .net 的 /gacha/record/query，不请求用户任意 URL，不自动跟随重定向。导入链接只提取记录授权参数，不能落日志或数据库；也支持标准导出 JSON 的本地导入。记录按账号、区服、池、稳定记录标识去重；来源角色必须匹配当前账号。提供各池次数、稀有度分布、五星/出金列表、导入覆盖时间；不展示保底断言。
- 历史使用项目本地 SQLite，按账号+区服隔离。成功采集追加历史（同内容可去重），记录源时间、采集时间、周期末及数据来源。切换账号不串档，退出后私有接口不可读到上个账号历史。
- 从本次启用起持续记录，尝试从已有快照及官方实际可用周期/导入记录回补。当前版本标签只能从真实公告识别；无法识别时显示开始记录日期，不硬编码版本。历史回补不能生成模拟旧成绩。
- UI 保持藏蓝/金色；适配桌面与窄屏。加载、缺数据、失效、部分错误、历史起点都要明确。角色详情按需读，不在打开页面时同时拉几十个角色。

## 验收

有意义的模拟测试覆盖数据变化、零值/缺失、未知角色拒绝、接口失败保留旧值、跨账号隔离、过期深塔、周期切换、导入重复/错误账号/恶意 URL、不完整历史。构建和浏览器检查必须通过。真实查询仅访问已经授权的官方查询接口；不发送短信、微信消息或上传第三方排行。
