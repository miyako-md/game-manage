# B 站官方动态资讯来源

## 使用

今日总览和游戏页底部的「B站官方动态来源」可以查看采集状态、触发增量采集、回补60天以及查看收入/过滤记录。资讯保留作者、动态 ID、正文、发布时间、原链接、日期依据和规则版本。

手游采用B站主来源、社区补充。当前启用鸣潮官方UID `1955897084`、异环官方UID `3546636978489848`。LOL不应用本逻辑，保持原采集及展示方式。在本地 `config.toml` 配置：

```toml
[bilibili_sources]
wuthering_waves = "1955897084"
nte = "3546636978489848"
```

`bilibili_history_days` 默认60、`bilibili_poll_seconds` 默认600（TOML 顶层配置）。首次/未完成回补会尝试全窗口；成功后按上次成功时间加重叠窗口增量采集。SDK 使用直连且保持 TLS 证书验证，不修改系统代理；本次环境代理导致本机查询502、B站请求412，而独立直连成功取得动态。

SDK `bilibili-api-python` 17.4.2 已安装并加入依赖范围。可匿名查询；匿名被限制时可在来源面板设置 Cookie。凭据使用既有 CredentialStore 加密落盘，不返回给浏览器、不记录到日志；写接口受本机 Origin 和应用请求头校验保护。没有复制参考项目的机器人发送逻辑，不点赞、不下载视频、不发送消息。

## 筛选口径

- 视频、直播推荐及转发视频全部排除。
- 抽奖、开奖、中奖动态排除；宣传标题中的 PV/EP/MV/OST、实机/角色/时装展示、社区创作等排除。
- 保留涉及游戏内版本更新、维护、活动、卡池/棋盘/研募等且正文存在有效具体日期的通知。
- 发布时间不算活动日期；`1.3版本` 不算 `1月3日`。缺失年份按发布时间邻近年份标注推断；日期依据保留原始文字，不直接生成日历事件。
- 长专栏先读取全文并核对作者UID、动态ID；无法完整读取时标为待核对，不凭截断摘要发布。图片里的时间暂不OCR。
- 过滤记录也保存，便于查看误判；已保存动态按 UID + 动态ID 幂等更新。

## 存储与接口

`bili_posts` 保存资讯及筛选审计，`bili_state` 保存来源任务状态，均位于现有 SQLite 数据库的独立表，不覆盖原游戏快照。失败保存已成功读取的页面并退避。公开来源异常不覆盖游戏账号状态。

- `GET /api/sources/bilibili`：来源与覆盖状态（只返回登录是否配置）
- `GET /api/sources/bilibili/nte/audit`：已收录/过滤记录
- `POST /api/sources/bilibili/nte/refresh?backfill=true`：异步回补
- `GET /api/games/nte/snapshot/news`：与原有资讯合并读取
- `POST /api/auth/bilibili-source/credentials`：本地加密保存可选登录信息
