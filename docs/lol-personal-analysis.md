# 英雄联盟个人战绩分析

参考项目：[miyako-md/LOLhelper](https://github.com/miyako-md/LOLhelper)，复核主分支提交 `c2dc013368086c318f35bbd1db32891f171e0f3a`（2026-09-26）。复用其个人战绩分析思路与 `pigeon/stats.py` v3 评分公式，并适配本项目的 FastAPI、SQLite 和 Vue 界面。没有引入原项目的 Flask 云端服务、车队权限、同步令牌或私人对局资料。

## 使用

1. 启动并登录英雄联盟客户端，打开本项目的英雄联盟模块。
2. 点击“采集客户端战绩”，读取最近窗口和双方详情。详情失败的场次仍保留基础记录；再次采集会重试。
3. 按时间和模式筛选，查看个人评分、每日趋势、活跃热力图、英雄表现、名场面与海克斯统计。
4. 关闭游戏客户端后，已归档战绩仍可浏览。更换账号后归档按账号隔离。

默认轮询也会累积 LCU 返回的基础战绩，查看单局实时详情时会补充归档。显式采集最多处理最近 20 场，详情请求并发为 4；重复采集按账号与对局 ID 去重，不以简略摘要覆盖完整详情。

数据保存在配置的 `db_path`（默认 `data/assistant.db`）中新增的 `lol_accounts` 和 `lol_matches` 表。LCU 登录令牌不写入数据库。阅读分析页面只访问本地归档与英雄名称缓存，不调用云端同步接口。

## 口径

- 胜负优先使用客观队伍结果；未知结果不计入胜率分母。本人未出场的记录不计入。
- 时间按北京时间自然日（零点）分组。LOLhelper 原来的逻辑日为凌晨 4 点，本项目为与其他模块保持一致而采用零点。
- 单局评分沿用 v3 的战斗 40%、伤害 30%、承伤 12%、控制 8%、经济 10%，以及 `SCORE_CALIB=0.74` 和展示分映射。没有胜负加分。
- 本方五名参与者与必要指标不完整时不评分，零与缺失分开处理；平均分仅计算有评分的场次。个人视图不使用车队榜单的小样本置信收缩。
- 这是 LOLhelper 参考评分，不是官方评分。公式原本面向海克斯大乱斗，其他模式仅供参考，不据此授予官方 MVP。
- 海克斯统计只纳入队列 2400，按本人选中的强化与组合计算本地样本场次及胜率。未取得强化列表的场次单独显示覆盖率。缺少可靠中文名称时显示强化 ID。
- 上游随源码携带的强化名称文件是占位数据，不能直接当作真实名称使用。同版本、同英雄的外部强化评级数据尚未接入，因此不产生“天胡／烂”等评级，更不会将当前版本评级套在历史版本上。

## 覆盖边界

本地档案从本机实际采集开始累积，不代表完整生涯。此次不迁移 LOLhelper 云端历史库，不启动上传服务；SGP 历史回补、车队排行、组队分析、日报推送及外部版本评级快照不在本次个人模块范围内。

接口：`GET /api/lol/analysis`、`GET /api/lol/matches/{match_id}`、`POST /api/lol/collect`。写入沿用本项目的 Host/Origin 校验和 `X-Game-Assistant: 1` 标记；客户端离线时显式采集返回 503，历史读取不受影响。
