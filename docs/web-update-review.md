# 网页更新检查记录

范围：右上角更新弹窗、固定官方主分支检查、Windows 本机助手、Linux 独立助手、发布版本标记和维护状态。此记录不代表已更新生产环境，也不替代首次安装后的主机验收。

## 用户流程与数据边界

- 打开弹窗才读取状态；点击“检查更新”才访问官方仓库。网页不能指定其他仓库、分支、下载地址或执行命令。
- 云端三个接口均要求网站管理员；写请求沿用会话和跨站请求伪造保护。本机入口沿用回环地址、来源和请求头限制。
- 更新请求保存当前提交和目标提交。助手重新核对官方主分支及提交祖先关系；领先、分叉、未知版本、本地修改或过期检查均不能执行更新。
- 界面断线只重读状态，不重发更新。只有任务完成、后端提交和界面提交均为目标版本时才显示成功。
- 维护阶段停止业务写入，新启动的服务也延后后台采集与通知；状态损坏或不可读时继续阻止业务请求。启动 QQ 或重新放行业务前先持久化不可恢复旧数据的边界，无法确定恢复结果时保留人工处理状态。

## 独立审查发现与修正

审查使用临时 Git 仓库、合成账号和隔离目录，未执行真实安装更新。

| 发现 | 修正与验收位置 |
| --- | --- |
| 构建目录中的 Git 钩子可能在高权限状态检查时运行 | 工作进程统一禁用 Git 钩子与文件监视钩子；真实临时仓库回归覆盖钩子不执行 |
| 助手若使用业务虚拟环境，依赖的 Python 启动代码可随助手获得高权限 | Linux 助手改用独立的受信任系统解释器和管理员安装的标准库模块副本，业务发布不能替换助手 |
| 构建留下的后台进程可通过已打开的文件描述符修改已检查源码 | Linux 构建使用独立控制组，清理全部子进程后才核对和冻结发布目录；真实 Linux 验证仅操作专用临时单元 |
| 内部健康请求的回环主机头不符合云端域名限制 | 保持连接回环地址，使用已验证配置中的主机头，不放宽公开入口 |
| Windows 手动重建原目录，实际却运行活动发布目录 | 启动入口统一解析已验证的活动目录；活动发布下拒绝 `-Rebuild`，避免目录错位 |
| 公开状态发布过程中短暂不可读，维护门禁可能放行业务 | 发布前设置读取权限，再原子替换；维护门禁对损坏和不可读状态关闭业务访问 |
| 旧 wheel 安装包可能借用当前源码目录的新提交号 | 默认运行版本来自实际源码包或安装包自身标记；安装包、发布清单和界面不一致时不报告就绪 |
| 新 API 在核对版本期间启动后台采集和通知，可能在产生外部效果后恢复旧数据 | 本地与云端在维护期延后后台启动；等待任务随服务退出取消。公开完成状态前先持久化禁止恢复旧数据的边界 |

主要回归位于 `tests/test_system_update_*.py`、`tests/test_release_build_metadata.py` 和前端 `system-update-*.test.js`。Windows 启动测试只运行临时目录中的脚本验证，拦截实际服务启停；Linux 特权隔离测试要求显式启用，仅使用临时目录和随机测试单元。

## 安全检查范围

| OWASP 类别 | 检查结果与边界 |
| --- | --- |
| A01 权限控制 | 管理员、普通用户、未登录与精确路由清单均有检查；没有新增任意系统路径白名单 |
| A02 密码学 | 沿用 HTTPS 校验和既有会话保护；不增加密钥存储或把私密配置写入更新记录 |
| A03 注入 | 请求仅接受固定结构和完整提交号；命令用参数列表传递，提交说明按文本显示 |
| A04 设计 | 检查排队、重复提交、重启、版本不一致和恢复边界；修正 Windows 双目录问题 |
| A05 配置 | 检查独立服务用户、共享状态权限、固定布局及健康请求域名；首次主机配置需管理员验证 |
| A06 依赖 | 使用 Python 和前端锁文件；未额外执行联网漏洞库扫描，不将锁定依赖等同于无漏洞 |
| A07 身份认证 | 沿用管理员会话和写请求保护；浏览器遇会话失效或管理员权限撤销停止等待 |
| A08 完整性 | 检查真实代码身份、目标提交、源码校验、独立助手运行环境及后台进程隔离 |
| A09 日志 | 对外只返回固定错误码和任务状态，不回传命令输出或秘密；当前任务记录不包含发起管理员身份 |
| A10 服务端请求伪造 | 仓库、主分支、检查地址固定；客户端无法指定网络目标 |
